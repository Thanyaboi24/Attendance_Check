# Thai / English (i18n)

Both apps use **i18next + react-i18next** with bundled resources (no network, no native module).

| | Mobile (`apps/mobile`) | Admin web (`apps/admin-web`) |
|---|---|---|
| Setup | `src/i18n/index.ts` (imported first in `index.ts`) | `src/i18n/index.ts` (imported first in `main.tsx`) |
| First language | Phone language (`th*` → Thai, else English) | Browser language (`th*` → Thai, else English) |
| User choice | Settings → Language; stored in the local `meta` table so background notifications use it too | Language switch (sidebar, login page); stored in `localStorage` |
| Text | `src/i18n/en/<namespace>.ts`, `src/i18n/th/<namespace>.ts` | same |
| Dates | `src/i18n/format.ts`: Thai day/month names, Buddhist Era year (2026 → 2569), 24-hour time | Tables keep `YYYY-MM-DD HH:mm` (sortable, matches CSV); friendly dates use Thai months + BE |

## Rules

- **English files are the contract.** Every key in `en/<ns>.ts` must exist in `th/<ns>.ts`
  (`satisfies Messages<typeof en>` fails the typecheck otherwise). Keys are also type-checked in `t('ns:key')`.
- Components use `useTranslation('<ns>')`; plain functions (models, use cases, notifications) use `t` from `src/i18n`.
- **Data is not translated**: names of people, departments, campuses/areas, reasons typed by users, IDs.
- API enums (`CHECK_IN`, `PENDING`, `CONFIRMED_INSIDE`, …) are translated at display time from a key per value.
- Exports (CSV) and API payloads stay English/ISO.
- Interpolation: `{{name}}`. Plurals: i18next `_one` / `_other` keys (Thai has no plural forms; give both the same text).
- Tests run in English (test setup forces `en`); Thai tests switch with `i18n.changeLanguage('th')`.
